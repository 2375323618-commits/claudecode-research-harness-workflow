# Skill: 迭代精修

> 初版产出 → 质量检查 → 反馈列表 → 修改 → 再检查 的标准化循环。
> 适用于数据分析结果、论文文稿、代码、图表等各类产出。
> 对应第9章 设计模式③：迭代精修。

---

## 1. 什么时候需要迭代精修

- ✅ 论文润色初稿出来后
- ✅ 统计模型结果出来后
- ✅ 图表初版出来后
- ✅ 代码跑通但需要优化
- ✅ 文献综述初稿需要完善
- ❌ 一次性能做对的小任务
- ❌ 小马明确说"先看个大概就行"

## 2. 标准流程

```
第一轮输出
    │
    ▼
[自我检查]  ← 检查质量
    │
    ├─ 发现 N 个问题 → 列出修改清单（带优先级）
    │
    ├─ 小马确认是否修改 → 等反馈
    │
    ├─ 执行修改 → 产出 v2
    │
    └─ 检查 v2
         │
         ├─ 还有问题 → 继续迭代
         └─ OK → 交付
```

### 2.1 自我检查清单

根据不同类型的产出，检查不同维度：

**数据分析结果**
- [ ] 数据清洗是否完整（缺失值/异常值已处理）
- [ ] 模型设定是否合理
- [ ] 诊断检验是否通过
- [ ] 结果解读是否有经济含义
- [ ] 结论是否与数据一致
- [ ] 图表的坐标轴、标签、图例是否清晰

**论文润色**
- [ ] 原意是否保持
- [ ] 语法/拼写是否正确
- [ ] 术语是否统一
- [ ] 逻辑是否通顺
- [ ] 学术风格是否一致
- [ ] 数据/引用是否未修改

**代码**
- [ ] 能否正常执行不报错
- [ ] 逻辑是否正确
- [ ] 是否有冗余代码
- [ ] 注释是否清晰
- [ ] 是否处理了边界情况

**图表**
- [ ] 数据是否正确
- [ ] 坐标轴范围是否合理
- [ ] 颜色/字体是否专业
- [ ] 信息密度是否合适
- [ ] 经济学风格是否一致

### 2.2 问题分级

| 级别 | 定义 | 处理方式 |
|---|---|---|
| 🔴 必改 | 事实错误、逻辑断裂、数据问题 | 立刻改 |
| 🟡 建议改 | 表述不清、图表可优化 | 建议修改，等小马确认 |
| 🟢 可优化 | 风格偏好、排版细节 | 标注但不强求 |

## 3. 迭代规则

- **每轮只解决当前级别的问题**，不一次性追求完美
- **每轮修改后必须重新检查**，防止修改引入新问题
- **最多迭代 3 轮**，3 轮后如果还有大问题，通知小马介入
- 每次迭代产出新版本，保留历史版本（如 `v1.md` → `v2.md`）

## 4. 输出格式

```
## 版本历史
- v1 [初始版本]: [时间]
- v2 [精修]: [时间]

## 修改记录
| # | 问题 | 级别 | 修改方式 |
|---|---|---|---|
| 1 | [问题描述] | 🔴/🟡/🟢 | [说明做了什么] |

## 当前版本
[修改后的内容]

## 下次迭代建议（如果有）
- [建议1]
- [建议2]
```

## 5. 示例

```
我跑完回归模型后：
→ 自我检查 → 发现异方差问题 → 列出修改清单
→ 报告小马: "模型跑完了，发现异方差问题（VIF偏高），建议加稳健标准误重跑"
→ 小马点头 → 执行修改 → 出 v2 → 再检查 → OK → 交付
```
