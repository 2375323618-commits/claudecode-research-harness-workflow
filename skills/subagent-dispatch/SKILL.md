# Skill: 子代理调度

> 复杂任务的拆解、并行分派与结果整合。将大任务拆成多个独立子会话并行执行，互不阻塞，各分支汇报后统一汇总。

## 重要说明

子代理通过 `sessions_spawn(mode="run")` 启动，执行状态为 `ok` 即代表完成。
子代理的产出通过**写入文件**（File Handoff）回传，而不是通过返回值。
子代理任务描述中必须包含明确的输出文件路径，以便汇总结结果。

---

## 1. 什么时候拆

### 应该拆（启动子代理并行）
- 超过 3 个独立步骤
- 需要多个不同数据源（如GDP数据 + 产业结构数据 + 国际贸易数据）
- 一个步骤的产出不需要等另一个步骤的产出
- 需要不同工具/方法处理不同部分（如一个人找数据、一个跑模型、一个画图）

### 不应该拆
- 简单任务（纯文字、查一个数据源、润色）
- 步骤之间有强依赖关系（下一步必须等上一步结果）
- 总执行时间预计 < 5 分钟

## 2. 怎么拆

### 判断并行可行性

```
子任务清单
  │
  ├─ 全部无依赖 → 全部并行（sessions_spawn 同时跑）
  │
  ├─ 部分有依赖 → 无依赖的先并行，有依赖的串行
  │
  └─ 全部有依赖 → 不拆，串行走主线
```

### 标准化拆解步骤

1. **任务分析**：识别主任务的独立模块
2. **依赖检查**：每个模块需要什么输入，谁需要谁
3. **角色分配**：给每个子任务指定对应代理角色
4. **并行启动**：用 `sessions_spawn` 启动多个独立会话
5. **结果收集**：各子会话完成后汇报
6. **小马确认**：展示各分支结果，等小马确认
7. **汇总合并**：整合所有分支结论

## 3. 子代理角色速查

| 角色 | 配置位置 | 适用场景 |
|---|---|---|
| data-searcher | agents/data-searcher.md | 搜数据源 |
| data-cleaner | agents/data-cleaner.md | 数据清洗 |
| model-runner | agents/model-runner.md | 跑模型 |
| viz-maker | agents/viz-maker.md | 画图 |
| paper-polisher | agents/paper-polisher.md | 论文润色 |
| lit-reviewer | agents/lit-reviewer.md | 文献综述 |
| task-organizer | agents/task-organizer.md | 任务拆解与汇总 |

## 4. 示例流程

```
小马: "分析2020-2025年GDP和CPI关系"
我(作为task-organizer):
  → 拆成3个子任务
    [A] data-searcher: 找GDP数据
    [B] data-searcher: 找CPI数据
    [C] model-runner: 跑相关性分析(需等A和B结果)
  → A和B并行spawn
  → A和B报结果 → 小马确认
  → 拿到数据后 spawn C
  → C报结果 → 小马确认
  → 汇总结论
```

## 5. 子代理通信规则

- **File Handoff**（核心方式）— 子代理的结果写入文件（data/ 或 literature/），父代理通过读取文件获取结果。子代理任务说明中必须指定输出文件路径，如 `将结果写入 data/subtask-result.md`
- **独立上下文** — 每个子会话不共享上下文，避免污染
- **错误隔离** — 一个子代理失败不影响其他子代理
- **状态确认** — `sessions_spawn` 返回 `status=ok` 即为完成
- **结果获取** — 父代理子代理完成后读取子代理写入的文件

### 标准通信模板

分派子代理时，任务描述必须包含：
```
你的角色：[角色名]
输入：[数据/文件路径]
任务：[要做什么]
输出要求：
  1. 结果保存到 [文件路径]
  2. 格式：[Markdown/CSV等]
```
